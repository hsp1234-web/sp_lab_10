第一部分：開發者可讀的總結報告

新台幣匯率風險儀表板 - 專案規劃總結與狀態報告 (v1.0)

生成時間: 2025-05-05 22:13:00 Asia/Taipei (UTC+8)

整體狀態: ⏳ 規劃階段完成，待開始開發 (Awaiting Development Start)

核心功能:

整合多維度金融數據 (市場、宏觀、情緒等)。

計算量化風險指標。

評估新台幣 (TWD) 匯率的綜合風險位階。

以清晰、互動的儀表板視覺化呈現風險狀況與關鍵驅動因素。

專案目標:

目標 1: 在 Google Colab 環境中，開發一個可運行的儀表板原型 (v1.0)，實現核心數據流、基礎風險評估和靜態視覺化 (對應開發計畫階段一)。

目標 2: 儀表板最終能提供兩層信息展示：快速總覽表格和詳細信息卡片。

目標 3: (階段二目標) 實現進階指標計算和風險評估邏輯，並加入互動式圖表。

目標 4: (階段三目標) 建立回測框架以驗證風險評估邏輯的有效性。

(ℹ️ 目標的可衡量指標將在開發過程中進一步細化，例如定義「基礎風險評估」的具體指標範圍和「互動式圖表」的具體功能。)

關鍵決策、假設與理由:

決策: 選擇 Google Colab 作為主要開發環境。

理由: 便於快速原型設計、整合 Python 生態系、利用免費計算資源、易於與 AI 協作。 (來源: 先前對話記錄/開發計畫總結)

決策: 採用模組化 Colab 儲存格設計。

理由: 遵循《通用模組化 Colab/Jupyter 專案設計準則 v3.3》，提高程式碼可讀性、可維護性、可測試性，方便分階段開發和 AI 協作。 (來源: 先前對話記錄/開發計畫總結)

決策: 最終儀表板採用兩段式佈局 (總覽表格 + 詳細卡片)。

理由: 根據使用者反饋，平衡快速掃描需求與詳細信息獲取需求，解決先前方案視覺雜亂問題。 (來源: 先前對話記錄/開發計畫總結)

決策: 優先使用 Colab Secrets 管理 API 金鑰。

理由: 根據《Colab 金融 API 最佳實踐》，此為 Colab 環境中最安全、便捷的方式。 (來源: 先前對話記錄/開發計畫總結)

假設: 規劃文件中提及的核心指標可通過選定的 API (Alpha Vantage, FRED, yfinance) 獲取足夠的歷史數據。

影響: 若數據獲取困難或質量不足，可能需要調整指標選擇或尋找替代數據源。 (來源: 4-1最終數據策略與 Colab 架構)

假設: 開發者具備必要的 Python、Pandas 及金融知識來理解和實現指標計算與風險邏जिक。

影響: 若技能不足，開發進度可能延遲或需要額外學習/支持。 (來源: 開發計畫總結)

(ℹ️ 風險判斷邏輯的具體方法（評分卡 vs. 模型）將在開發階段二做出最終決策。)

環境需求:

Python 版本: 預計 3.10.x (ℹ️ 待 Cell 1 實際執行確認)

關鍵函式庫: pandas, numpy, requests, requests-cache, python-dotenv (若用 Drive), yfinance, fredapi, tenacity, plotly, ipywidgets (ℹ️ 具體版本待 Cell 1 安裝後確認)

硬體加速器: 無特別需求 (預設 Colab 環境)

外部數據源: Alpha Vantage API, FRED API, Yahoo Finance API, Google Drive (用於日誌/緩存持久化)
