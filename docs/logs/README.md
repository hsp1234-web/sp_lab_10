# 開發日誌系統說明

本目錄採用結構化的日誌管理系統，每個開發日誌都是獨立的 Markdown 檔案。

## 目錄結構

```
docs/logs/
├── YYYY-MM/              # 按月份分類
│   ├── YYYY-MM-DD_HH-MM_description.md
│   └── ...
└── README.md             # 本說明檔
```

## 檔名格式

**標準格式**：`YYYY-MM-DD_HH-MM_brief-description.md`

**範例**：
- `2025-11-22_20-15_v9.1_structure_optimization.md`
- `2025-11-22_19-55_project_restoration.md`
- `2025-11-21_21-30_windows_compatibility.md`

## 日誌內容格式

每個日誌檔案應包含以下結構：

```markdown
# [標題]

**日期**: `YYYY-MM-DD HH:MM:SS CST`  
**作者**: [作者名稱]

## 摘要
[簡要說明本次變更的目的與背景]

## 主要變更
[詳細列出所有重要變更]

## 驗證結果
[說明如何驗證變更，以及驗證結果]
```

## 建立新日誌

### 方法 1：使用自動化工具（推薦）

```bash
python utils/create_log.py
```

此工具會：
- 自動取得當前台北時間
- 生成標準化檔名
- 建立包含模板的日誌檔案
- 提示您填寫內容

### 方法 2：手動建立

1. 在對應的月份目錄下建立新檔案
2. 使用標準檔名格式
3. 複製上述內容格式模板
4. 填寫日誌內容

## 時區規範

所有時間戳記必須使用 **亞洲/台北 (Asia/Taipei)** 時區，並標註 `CST`。

## 注意事項

- ✅ 每個日誌都是獨立檔案，便於版本控制
- ✅ 按月份分類，易於檢索與管理
- ✅ 檔名包含時間與簡短描述，一目了然
- ✅ 符合現代開發實踐與團隊協作需求
