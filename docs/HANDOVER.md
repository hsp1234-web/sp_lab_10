**文件版本**: 1.0

## 1. 專案目標與核心理念

本專案旨在建立一個高效、自動化且易於擴展的量化交易回測環境。其核心目標是快速迭代、測試並驗證以**風險控制**（特別是將月度最大回撤控制在 1-6%）為首要目標的交易策略。

經過本次重構，專案已從一個混雜的腳本集合，轉變為一個以 `lo2cin4bt` 回測框架為核心的、由設定檔驅動的現代化研究平台。

## 2. 核心工作流程 (Standard Operating Procedure)

整個量化研究流程被設計為一個清晰的四步閉環。請嚴格遵循以下順序：

### **步驟 1：建立／更新市場數據庫**

所有回測的數據來源均為一個位於 `data/yfinance.db` 的 DuckDB 資料庫。若要首次建立，或更新數據至最新，請執行：

```bash
python3 scripts/build_yfinance_db.py
```

*   **作用**：此腳本會自動從 `yfinance` 下載 Ticker 列表中的所有 OHLCV 數據，執行 ETL (提取-轉換-載入) 流程，並將乾淨、標準化的數據存入資料庫。
*   **客製化**：可直接修改腳本內的 `TICKERS` 列表，以增刪您想研究的標的。

### **步驟 2：設定回測參數**

所有回測任務均由一個 JSON 設定檔驅動。主要的設定檔位於：

`config/quick_feedback.json`

*   **作用**：您可以在此檔案中定義所有回測的關鍵參數，包括：
    *   `job_name`: 本次任務的唯一識別名稱。
    *   `data`: 要回測的標的 (`symbol`) 及時間範圍。
    *   `strategy`: 策略名稱及其參數範圍 (`params_range`)。
    *   `trading`: 初始資金、交易成本等。
*   **實驗**：若要測試不同策略或標的，**推薦複製此檔案**並重新命名（例如 `config/0050_rsi_test.json`），然後在執行時指定新的設定檔。

### **步驟 3：執行回測**

當數據庫與設定檔都準備好後，執行核心的回測腳本：

```bash
python3 scripts/run_quick_feedback.py --config config/your_config_name.json
```
*   **作用**：此腳本會自動讀取指定的設定檔，從資料庫加載數據，並驅動 `lo2cin4bt` 的增量回測引擎 (`IncrementalBacktestEngine`) 執行所有參數組合的回測。
*   **即時回饋**：在執行過程中，終端機將**即時打印**出每個參數組合的**月度績效報告**，讓您能快速判斷策略的有效性。
*   **結果儲存**：所有詳細的回測結果（包含每筆交易、權益曲線等）都會被自動、增量地寫入設定檔中定義的輸出資料庫（預設為 `output/results/quick_feedback.db`）。

### **步驟 4：檢視與分析結果**

回測執行完畢後，使用結果檢視器來查看績效排名：

```bash
python3 scripts/view_results.py --db output/results/your_results.db --job your_job_name
```

*   **作用**：此腳本會連接到指定的結果資料庫，讀取特定 `job_name` 的所有回測績效，並在終端機中打印一個以**夏普比率 (Sharpe Ratio) 從高到低排序**的績效總覽表。
*   **快速分析**：這能讓您在一秒內找出在本次任務中，表現最好的參數組合。

## 3. 專案架構概覽

-   `AGENTS.md`: AI 代理協作的核心規範，**必須遵守**。
-   `lo2cin4bt-main/`: 外部整合的核心回測框架，功能強大但我們只透過我們自己的腳本與其互動。
-   `config/`: 存放所有 JSON 回測設定檔的目錄。
-   `data/`: 存放數據庫檔案 (`.db`) 的目錄。
-   `docs/`: 存放專案文件，如本交接文件和開發日誌。
-   `output/`: 存放所有自動產生的結果，包括日誌和回測結果資料庫。
-   `scripts/`: **我們的主要工作目錄**，存放所有可執行的核心腳本。
-   `archive/`: 存放所有在本次重構中被廢棄的舊 `src` 腳本，僅供歷史參考。
-   `main.py`: 專案的根執行入口，其唯一作用是調用 `src/main.py`。
-   `requirements.txt`: 專案的 Python 依賴列表。

## 4. 關鍵設計決策

*   **數據中樞 (DuckDB)**：我們選擇 DuckDB 作為數據倉儲，因其專為分析型查詢設計，速度遠超 SQLite，且與 `lo2cin4bt` 框架原生整合。
*   **ETL 數據管道**：我們採用了經典的 ETL 模式來處理數據，確保了寫入資料庫的數據是 100% 乾淨和標準化的，從而避免了在回測階段進行複雜的數據清洗。
*   **即時回饋引擎**：我們客製化了 `IncrementalBacktestEngine`，在其中注入了計算並打印月度績效的邏輯，這是實現「快速迭代」核心需求的關鍵。
*   **設定檔驅動**：整個工作流程由 JSON 設定檔驅動，實現了研究邏輯與程式碼的解耦，大幅提升了進行大量不同實驗的效率和便利性。

## 5. 後續開發建議

*   **實現真實策略**：當前的 `MovingAverage` 策略只是一個佔位符。下一步的核心工作是在 `lo2cin4bt` 框架內，實現一個能產生有效交易訊號的真實策略邏輯。
*   **豐富績效指標**：目前的即時回饋和最終報告只包含了基礎的幾個指標。可以擴展 `IncrementalBacktestEngine` 和 `view_results.py`，加入更多您關心的績效指標（如 Sortino Ratio, Calmar Ratio, 年化報酬率等）。
